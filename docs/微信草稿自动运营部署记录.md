## 服务端部署

Content Ops 的生产代码目录为 `/opt/content-ops/release`，运行服务如下：

| 服务 | systemd 单元 | 状态 |
| --- | --- | --- |
| API | `content-ops-api.service` | 已验证为 `active` |
| 后台任务与调度 | `content-ops-worker.service` | 已验证为 `active` |

两个服务均从 `backend/.env` 读取运行环境变量。检索服务所需的 Tavily 密钥已写入该环境文件；密钥值不得记录在仓库、文档、聊天记录或前端配置中。

服务配置或代码更新后，使用以下命令使其生效：

```bash
systemctl restart content-ops-api.service content-ops-worker.service
systemctl is-active content-ops-api.service content-ops-worker.service
```

## 运维与风险

- 当前使用 SQLite，并发任务过多时可能再次出现数据库锁竞争。已启用 WAL 与 30 秒 busy timeout；任务量上升后应改用 PostgreSQL 或确保同一时间只运行一个生产任务。
- 部分资讯源可能偶发网络、TLS 或翻译解析失败；本次成功试跑证明主流程可用，但不代表每个来源始终可用。
- 草稿应在公众号后台人工复核事实、标题、配图和合规性后再发布。尤其不要因自动草稿存在而跳过事实核验。
- 内容库中存在一篇更早的草稿，含可能需要进一步核查的表述；本次未删除或修改该草稿。

## 日常检查

1. 在 Content Ops 查看最新任务是否于每日 09:30 创建并完成。
2. 在内容库检查文章是否带有“微信草稿”状态。
3. 在公众号后台复核草稿后，人工决定是否发布。
4. 若连续失败，先查看 `content-ops-worker.service` 日志、资讯源可用性和模型响应，再检查环境变量是否缺失。
